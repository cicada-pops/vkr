# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Разработка веб-платформы SQLHunt для изучения языка SQL на основе интерактивных детективных задач

**Авторы:** Якшин Артемий, Преображенский Артемий

**Вклад участников:**

- **Якшин Артемий** — клиентская часть SQLHunt (карточки дел, редактор запросов, визуализатор схемы базы данных, интеграция с API); в отчёте — обзор и сравнение аналогов (раздел 3).
- **Преображенский Артемий** — серверная часть SQLHunt (модель данных «полицейского архива», генератор данных, загрузка дел, выполнение и проверка запросов, аутентификация, тесты); в отчёте — обзор литературы (раздел 2).
- **Совместно** — состав исследователей, организаций и площадок (раздел 1), итоги, цель и задачи (раздел 4).

**Проект:** SQLHunt — браузерная игра, в которой игрок-следователь раскрывает дела с помощью SQL-запросов к базе данных расследований.

### Выводы по обзору

1. **Трудности новичков хорошо изучены.** Ошибки и заблуждения при составлении SQL-запросов систематизированы [1–3, 14]: чаще всего студенты ошибаются в соединениях, группировке и подзапросах. Эти классификации можно использовать для построения последовательности заданий и подсказок.
2. **Сюжет и игровые механики работают, но не автоматически.** Геймификация курса SQL повышает результаты и мотивацию [6, 15], SQL Island получает положительные оценки студентов [8], сюжетные задачи активизируют самостоятельную работу [16]. При этом награды сами по себе обучения не улучшают [7]: эффект даёт нарратив, встроенный в учебное действие [9].
3. **Автоматическая проверка и безопасность — отдельная задача.** Системы проверки SQL уязвимы для обхода [13], а метаданные PostgreSQL дают удобный инструмент проверки и описания схемы [12]. Интеллектуальные системы вроде SQL-Tutor [5] показывают, как давать обратную связь по ошибкам.
4. **Нерешённые вопросы.** Мало работ о сложных конструкциях SQL [2]. Сюжетные SQL-игры описаны как короткие однократные квесты [4, 8] без последовательной прогрессии. Русскоязычные работы посвящены тренажёрам [10] и геймификации вообще [11, 15], но не сюжетному обучению SQL.

Для SQLHunt из обзора следуют подходы: последовательность дел по таксономии ошибок [1, 3]; сюжет, неотделимый от запроса [9]; опыт как средство открытия нового материала, а не самоцель [7]; изоляция учебной базы и серверная проверка [13]; оценка по MEEGA+ и SUS [8, 15].

## 3. Обзор и сравнение аналогов

### Прямые аналоги

Решения, в которых SQL изучается через сюжетную игру.

- **[SQL Murder Mystery](https://mystery.knightlab.com/)** (Northwestern University Knight Lab). Одно дело об убийстве в вымышленном SQL City: игрок пишет запросы к базе SQLite, которые выполняются в браузере через SQL.js. Код открыт, есть пошаговое руководство для новичков, схема дана картинкой.
  *Ограничения:* одно дело; нет прогрессии и учётной записи; только английский язык; диалект SQLite.
- **[SQL Island](https://sql-island.informatik.uni-kl.de/)** (RPTU Kaiserslautern-Landau). Текстовый квест о выживании на острове после авиакатастрофы, персонажем управляют SQL-командами [4, 8]. Без регистрации, есть сохранение по ID игры, режим песочницы и сертификат.
  *Ограничения:* одна история примерно на час; схема — список таблиц текстом; нет русского языка (DE, EN, ES, PT, FR, HU); охват ограничен базовыми конструкциями.
- **[SQL Police Department](https://sqlpd.com/)**. Детективные миссии с брифингами и рангами следователя.
  *Ограничения:* запрос собирается из кликабельных фрагментов, а не пишется вручную; агрегаты, группировка и JOIN только запланированы; платная лицензия; английский язык.

### Косвенные аналоги

Решения, которые тренируют написание SQL-запросов без сюжета.

- **[SQL-EX.RU](https://sql-ex.ru/)**. Упражнятор с автоматической проверкой результата: 192 задачи на SELECT на обучающем этапе, 242 — на рейтинговом, 68 задач на изменение данных. Рейтинги и сертификат, бесплатно, русский и английский языки.
  *Ограничения:* абстрактные учебные базы без сюжета; рейтинговый этап на MS SQL Server; с задачи № 3 действует ограничение по времени, а с задачи № 139 запрос должен работать не медленнее авторского решения, что отсекает новичков.
- **[Stepik: «Интерактивный тренажер по SQL»](https://stepik.org/course/63054/promo)** (ДВФУ). 22 урока и 173 интерактивные задачи с ростом сложности от одной таблицы до учебных баз «Интернет-магазин», «Тестирование», «Абитуриент». Бесплатно, на русском языке.
  *Ограничения:* нет сюжета и игровой прогрессии; MySQL 8; линейный формат онлайн-курса.
- **[karpov.courses: «Симулятор SQL»](https://karpov.courses/simulator-sql)**. 150 задач с автопроверкой на PostgreSQL и Redash, ролевая рамка «аналитик сервиса доставки». Бесплатно, нужна регистрация.
  *Ограничения:* роль задана, но сквозного сюжета и игровой прогрессии нет; ориентирован на аналитиков данных.
- **[SQL Academy](https://sql-academy.org/ru)**. Интерактивный курс (60+ тем) и тренажёр (200+ задач, часть — с собеседований), рейтинг пользователей. Базовая часть бесплатна, Premium — 3 690 ₽ за 6 месяцев.
  *Ограничения:* нет сюжета; подсказки с ИИ и эталонные решения только в платной версии.
- **[SQLZoo](https://sqlzoo.net/)**, **[SQLBolt](https://sqlbolt.com/)**, **[PgExercises](https://pgexercises.com/)**. Бесплатные учебники с упражнениями в браузере; PgExercises работает на PostgreSQL.
  *Ограничения:* нет сюжета и прогрессии; в основном английский язык; абстрактные учебные базы (в PgExercises — три таблицы клуба: members, facilities, bookings).
- **SQL-Tutor** (University of Canterbury) [5, 7]. Интеллектуальная обучающая система с моделью знаний студента и обратной связью по ошибкам.
  *Ограничения:* академический инструмент для курсов университета, без сюжета, на английском языке.

### Выводы по сравнению

**Что можно использовать из существующих решений:**

- Из SQL Murder Mystery — формат «дело → вопрос → ответ одним значением», который проверяется однозначно.
- Из SQL Island — пошаговое введение для новичков и игровой сертификат.
- Из SQL-EX.RU и Stepik — большой банк задач с автопроверкой и ростом сложности как источник идей для новых дел; идея разбора типичных ошибок [14].
- Из karpov.courses и PgExercises — работа на PostgreSQL, принятом в учебном процессе [17].

**Какие ограничения устраняет SQLHunt:**

1. Рассмотренные сюжетные SQL-игры либо состоят из одной истории (SQL Murder Mystery, SQL Island), либо требуют платной лицензии и не дают писать запрос вручную (SQL Police Department). Ни одна из них не локализована на русский язык. SQLHunt предлагает серию бесплатных дел на русском языке.
2. SQL Murder Mystery выполняет запросы к SQLite в браузере, у остальных сюжетных игр СУБД не указана. SQLHunt выполняет запросы на сервере в PostgreSQL — том же диалекте, что изучается в вузе.
3. Русскоязычные тренажёры дают большой объём задач, но без сюжета и игровой прогрессии. В SQLHunt новые дела открываются по мере накопления опыта, а сложность растёт от простых выборок до оконных функций и CTE.
4. Схема базы в аналогах показана картинкой или текстом либо не показана вовсе. В SQLHunt схема строится по метаданным базы для конкретного дела, с описаниями полей на русском языке и ER-диаграммой.

**Что остаётся сделать:**

- реализовать подсказки по типичным ошибкам, как в SQL-Tutor;
- добавить поддержку рекурсивных CTE, которые сейчас блокирует валидатор запросов;
- провести апробацию с измерением эффекта.

## 4. Итоги

**Итоговая тема ВКР:** Разработка веб-платформы SQLHunt для изучения языка SQL на основе интерактивных детективных задач

**УДК для тезиса:** 004.655.3:378.147

- 004.655.3 — «Языки манипулирования данными», включая языки запросов и SQL;
- 378.147 — «Методы обучения. Формы преподавания» в высшей школе.

**Ключевые слова:** SQL, обучение SQL, язык запросов, PostgreSQL, геймификация, игровое обучение, сюжетные задания, детективные задачи, тренажёр, автоматическая проверка запросов, веб-платформа.

### Актуальность исследования

Язык SQL — обязательный навык для разработчиков, аналитиков и инженеров данных, и его изучение входит в программы ИТ-направлений вузов. При этом новички систематически допускают одни и те же логические ошибки [1, 3]. Исследования обучения SQL сосредоточены на базовых запросах, а сложные конструкции изучены слабо [2]. Учебные задачи обычно строятся на абстрактных базах из нескольких таблиц, которые не создают мотивации разбираться в данных.

Игровые механики и сюжет повышают результаты и мотивацию при изучении SQL и программирования [6, 8, 15, 16]. Эффект даёт нарратив, встроенный в учебное действие, а не сами награды [7, 9]. В России тему тренажёров и геймификации развивают, в том числе в Университете ИТМО [10, 11], а свежие работы 2025–2026 годов [12, 15, 16] показывают, что интерес к ней растёт.

Сравнение аналогов выявило пробел. Рассмотренные сюжетные SQL-игры (SQL Murder Mystery, SQL Island, SQL Police Department) не имеют русской версии и либо ограничены одной историей, либо требуют платной лицензии; SQL Murder Mystery работает на SQLite в браузере. Русскоязычные тренажёры (SQL-EX.RU, Stepik, karpov.courses, SQL Academy) не используют сюжет. Платформы, которая на русском языке и на PostgreSQL [17] вела бы учащегося через серию сюжетных дел от простых выборок до оконных функций и CTE, сейчас нет. Это и обосновывает разработку SQLHunt.

### Цель исследования

Разработать веб-платформу SQLHunt для изучения языка SQL на интерактивных детективных задачах. Платформа должна безопасно выполнять пользовательские запросы к учебной базе PostgreSQL, автоматически проверять ответы и обеспечивать последовательное освоение конструкций SQL — от простых выборок до оконных функций и общих табличных выражений.

### Задачи исследования

1. Проанализировать литературу по обучению SQL, типичным ошибкам новичков, геймификации и нарративу в обучении; сравнить существующие решения.
2. Сформулировать требования к платформе и спроектировать архитектуру: клиент, сервер, изолированные базы данных пользователей и расследований, очередь асинхронного выполнения запросов.
3. Разработать модель данных «полицейского архива» и генератор синтетических данных для фона дел.
4. Разработать сценарий дел нарастающей сложности, сопоставив каждое дело с группой конструкций SQL и типичных ошибок [1, 3].
5. Реализовать безопасное выполнение пользовательских запросов и автоматическую проверку ответа:
   - разрешён только SELECT;
   - доступны только таблицы текущего дела;
   - число строк в результате ограничено;
   - учебная база изолирована от базы пользователей.
6. Реализовать систему прогрессии по опыту и визуализатор схемы базы данных с описаниями полей.
7. Разработать механизм подсказок по типичным ошибкам в запросах.
8. Провести апробацию платформы на группе студентов и оценить игровой опыт и удобство использования (MEEGA+ [8], SUS [15]).

### Датасеты и сервисы

**Данные.** Используется собственный синтетический датасет. Реальные данные о людях и уголовных делах использовать нельзя: это персональные данные. Открытые учебные базы не содержат связанного сюжета с подброшенными уликами. Поэтому база расследований заполняется собственным генератором данных. Он использует библиотеку Faker и справочники:

- 69 описаний уголовных дел;
- 69 текстов показаний;
- 106 статей Уголовного кодекса;
- словари внешности и одежды.

По умолчанию создаются 1 500 человек, 500 подозреваемых и 100 обвинений, а также алиби, места преступлений и улики. Поверх фоновых данных загрузчик дел добавляет сюжетные записи каждого дела. База пересоздаётся одной командой. Сюжетные записи дел фиксированы, а если ответ зависит от фоновых данных, он пересчитывается контрольным запросом после генерации. Данные вымышлены и не нарушают ничьих прав.

**Сервисы.** Внешние платные сервисы для исследования не требуются: всё разворачивается локально через Docker Compose.

- PostgreSQL 17 — две базы: пользователи и прогресс; учебная база расследований.
- RabbitMQ и Celery — асинхронное выполнение пользовательских запросов.
- Redis — защита от перебора паролей.

Для апробации понадобятся анкеты MEEGA+ и SUS — открытые методики оценки, которые не требуют специальных сервисов.

**Открытый аналог для сравнения.** Код SQL Murder Mystery открыт ([MIT](https://github.com/NUKnightLab/sql-mysteries)), его можно использовать как эталон при сравнении сценариев дел.
